# 面试复盘：设计取舍与改进

## 值得讲的工程点

- JWT + Filter 实现无状态登录校验，前端 Axios 拦截器统一携带 token，401 后跳转登录。
- MyBatis XML 动态 SQL 根据可选条件拼接查询，并保留条件为空时查询全部的行为。
- 地区田地数量使用左连接和聚合，避免没有田地的地区从结果集中消失。
- `@Scheduled` 每天定时拉取天气数据，手动处理 GZIP 响应并关联田地和地区。
- 摄像头页面卸载时按顺序执行停止预览、登出设备、销毁插件，避免插件残留。
- 前端根据省份选择动态请求城市数据，减少一次性加载全部省市的资源浪费。

## 主动承认的问题

- 密码未加密，JWT 密钥硬编码，权限只区分管理员和访客。
- 外部接口地址、摄像头 IP、截图路径和天气 Key 直接写在代码中。
- Mapper 中存在隐式连接，表结构只靠 SQL 约定，缺少迁移工具。
- 天气定时任务直接串行调用外部服务，失败后没有补偿或告警。
- 摄像头插件依赖浏览器插件，兼容性差。
- 没有自动化测试，主要是黑盒手工测试。

## 重构方向

1. 用 Spring Validation 统一参数校验，用统一异常处理返回结构化错误。
2. 密码使用 BCrypt，JWT 密钥从配置中心读取，增加刷新和撤销机制。
3. 外部 API 地址和凭据全部改为环境变量，加入超时、重试、限流和日志。
4. 使用 Flyway/Liquibase 管理数据库迁移，给外键和查询条件补索引。
5. 将摄像头和推理服务解耦，改用标准上传接口和异步任务。
6. 为 Controller、Service 和前端关键组件增加自动化测试。
